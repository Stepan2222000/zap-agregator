## О проекте

**AutoHub AI** - это маркетплейс автозапчастей с интеграцией искусственного интеллекта. Проект должен производить впечатление крупного корпоративного решения.

### Ключевая концепция
Платформа упрощает публикацию объявлений о продаже автозапчастей:
- Продавец указывает артикул, загружает фото и базовую информацию
- Google Gemini AI автоматически обогащает объявление структурированным описанием
- Модератор проверяет и одобряет объявления перед публикацией
- Покупатели ищут запчасти по артикулам через удобный интерфейс

### Основные особенности
1. **Нет системы регистрации** - низкий барьер входа для продавцов
2. **AI-обработка объявлений** - автоматическое обогащение данных через Google Gemini
3. **Обязательная модерация** - контроль качества контента человеком
4. **Двойная идентификация** - внешние артикулы + внутренние ID
5. **Mobile-first** - приоритет мобильной версии над десктопной
6. **Корпоративный дизайн** - современный, необычный UI/UX

## Технологический стек

### Backend
- **Фреймворк:** Python FastAPI
- **База данных:** PostgreSQL
- **Работа с БД:** Напрямую через psycopg2/asyncpg (БЕЗ SQLAlchemy ORM)
- **AI Integration:** Google Gemini API
- **Архитектура:** Layered (Controllers → Services → Repositories)

### Frontend
- **Фреймворк:** Next.js (App Router)
- **Рендеринг:** CSR с частичным SSR для SEO
- **Стилизация:** Tailwind CSS
- **State Management:** React Context API + useState/useReducer
- **Иконки:** Heroicons или Lucide

### Структура проекта (Monorepo)
```
zap-agregator/
├── backend/          # Python FastAPI приложение
├── frontend/         # Next.js приложение
├── shared/           # Общие типы и константы
├── docs/             # Документация (PRD и др.)
└── scripts/          # Утилиты и миграции БД
```

## Правила разработки

### 1. Архитектурные принципы

#### Backend
- **НЕ использовать ORM** - работа с PostgreSQL только через чистый SQL
- **Модульная структура** с разделением на слои:
  - `api/` - роутеры и эндпоинты
  - `services/` - бизнес-логика
  - `schemas/` - Pydantic модели для валидации
  - `db/` - работа с базой данных
- Все конфигурации в `core/config.py` (API ключи, настройки модели)
- RESTful API для взаимодействия с фронтендом

#### Frontend
- **App Router Next.js** - использовать новую структуру маршрутизации
- **Mobile-first подход** - начинать разработку с мобильной версии (375px-430px)
- **Компонентный подход** - переиспользуемые React компоненты
- Tailwind CSS для всех стилей (без CSS-in-JS)

### 2. UI/UX правила

#### Дизайн
- **Тёмная тема по умолчанию** с возможностью переключения на светлую
- **Цветовая схема (темная):**
  - Фон: #0A1628, #0F172A
  - Карточки: #FFFFFF, #F8FAFC (светлые на темном фоне)
  - Акцент: #3B82F6, #2563EB (электрический синий)
- **Корпоративный стиль:**
  - Generous whitespace (много "воздуха")
  - Скругленные углы (rounded-xl, rounded-2xl)
  - Мягкие тени (shadow-lg, shadow-xl)
  - Градиенты в акцентных элементах
  - Качественные иконки

#### Мобильная оптимизация
- Минимальный размер touch-элементов: **44x44px**
- Минимальный размер шрифта: **16px** для основного текста
- Крупные, заметные кнопки
- Вертикальная прокрутка, минимум горизонтальных взаимодействий
- Swipe-жесты для фотогалереи

#### Анимации
- Smooth transitions для hover (0.2-0.3s)
- Fade-in для загрузки контента
- Skeleton loaders для данных
- Micro-interactions на кнопках (scale, ripple)
- **НЕ использовать** чрезмерные анимации

### 3. Функциональные требования

#### Публикация объявлений
- Форма без регистрации с полями: артикул, до 10 фото, состояние, цена, марка, описание, контакты
- После публикации → автоматическая отправка на обработку Gemini API
- Success модалка после успешной публикации

#### AI-обработка
- Google Gemini ищет информацию по артикулу
- Формирует структурированное описание и характеристики
- При ошибке AI → объявление в статус "На модерации" с пометкой об ошибке
- Модератор может повторно отправить на обработку неограниченно

#### Модерация
- Обязательная для всех объявлений
- Админка с фильтрацией по статусам: "В обработке AI", "На модерации", "Одобрено", "Отклонено"
- Модератор видит исходные данные + результаты AI
- Действия: одобрить, отклонить, повторить AI-обработку
- Модератор вручную создает внутренний ID и привязывает артикулы

#### Поиск и каталог
- Главная страница: hero-блок, поисковая строка, кнопка публикации, 12 брендовых карточек
- Поиск по артикулу и названию (текстовое совпадение)
- Фильтры: диапазон цены, состояние, марка автомобиля
- Empty state: "Такого товара нет" (без показа похожих)

### 4. База данных

#### Основные таблицы
- `listings` - объявления
- `parts` - запчасти (внутренние ID)
- `article_numbers` - артикулы (связь many-to-one с parts)
- `brands` - марки автомобилей
- `images` - фотографии

#### Правила работы с БД
- Использовать чистый SQL (без ORM)
- Connection pooling для оптимизации
- Индексы на часто запрашиваемые поля (артикулы, названия)
- Транзакции для критичных операций

### 5. Обработка ошибок и состояний

- **Все loading состояния** должны быть корректно обработаны (skeleton loaders)
- **Все error состояния** должны показывать понятные сообщения пользователю
- Корректная обработка ошибок Gemini API
- Валидация на клиенте и сервере (Pydantic схемы)

### 6. Что НЕ нужно делать в MVP

❌ Система аккаунтов/регистрации
❌ Автоматическая валидация артикулов
❌ Рекомендации похожих товаров
❌ Капча
❌ Reviews/ratings
❌ Чат с продавцом
❌ Wishlist/избранное
